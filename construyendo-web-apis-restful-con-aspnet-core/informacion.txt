	Cabecera.
	Cuerpo. (codigo html)

TIEMPO DE VIDA DE SERVICIOS
-Transient = la de menor tiempo de vida,se crea una instancia nueva del servicio cada vez que se solicite se utiliza cuando no hay estado compartido, es decir cuando la clase no tiene campos que queramos compartir entre instancias

-Scoped = es cuando se crea una instancia unica por peticion http, es decir no importa cuantas veces se solicite el servicio siempre que sea del mismo contexto http se entrega la misma instancia (util para preservar estado dentro de una solicitud http)

-Singleton = se crea una unica instancia del servicio durante la vida de la aplicacion , no importa cuantas veces se solicite el servicio, siempre se entregará la misma instancia aunque sea a usuarios distintos (util cuando queremos tener un estado global como por ejemplo como una capa de cache) (por ejemplo cuando se ejecuta una peticion http y se guarda en memoria alguna informacion y en una segunda peticion http diferente se puede recuperar o modificar esa informacion)

Filtros

-los filtros nos ayudan a correr codigo en determinados momentos del ciclo de vida del procesamiento de una peticion http.

-son utiles para evitar repetir codigo

-Fitro de autorizacion (filtro mas usado)

Tipos de filtro:
	-Filtros de autorizacion (son los que determinan si un usuario puede consumir una accion o endpoint en especifico)
	-Filtros de recursos (se ejecutan despues de la etapa de autorizacion, usados para validaciones generales o implementar una capa de cache personalizada)
	-Filtros de accion (se eejcutan justos antes y justo despues de la ejecucion de una accion, se pueden usar para manipular los argumentos enviados a una accion o a la infromacion retornada por los mismos)
	-Filtros de excepcion (se ejecutan en excepciones no atrapadas por los try catch, y durante binding del modelo )
	-Filtros de resultados (se ejecutan antes y despues de la ejecucion de un AccionResult)	
	
	
-la idea es que estos filtros ademas puedn detener la tuberia de filtros de tal modo que ni los demas filtros ni la accion del controlador se ejecuten

LUGARES DONDE SE PUEDEN APLICAR Filtros
-se puede aplicar filtros a nivel de acciones (es el ams simple, se ejecuta antes o despues de la creacion de una accion)
-tambien se pueden colocar a nivel de controlador (de tal modo que aplique a todas las acciones de un controlador, se colocan como atributos )
-tambien se pueden usar filtros globales a nivel de todo el web api (de modo que los filtros aplicque a todas o a todo el controlador)

-para crear un filtro se crea una clase la cual va a implementar las interfaces ActionFilter o IAsyncActionFilter

-si se usan filtros globales en program.cs se debe deshabilitar el cache porque si el cache está activo no se ejecuta la accion y si no se ejecuta laccion tampoco el filtro de accion *

=======================================================================================
Pruebas Automaticas

-Una prueba automaticaes un software que prueba nuestro software

-Una de las principales ventajas de las pruebas automaticas es que ellas prueban todo lo que le digamos que prueben, todas las veces que queramos

Cualidades de una Buena Prueba Automatica:
	-Razonablemente consistente = la idea es que el resultado variará solo cuando el software cambie, es decir  corremos una prueba y es exitosa y sin hacer cambios en la prueba la segunda preuba debe ser exitosa

	-No depende de otra prueba (las pruebas deben ser independientes, nunca debe ser el caso de que para que la prueba B funciene debe ser el caso de la prueba A)

	-No realiza cambios Externos = no debe realizar cambios en el sistema, debe probar y dejar las cosas como estaba, en algunos casos si se acepta cierta flexibilidad   

-tipicamente una prueb automatica es una funcion la cual preuba alguna parte de la aplicacion
-POR EJEMPLO: un software de ventas, una prueba podria ser la parte de la aplicaicon que crea un producto

-A un conjunto de Pruebas Automaticas se le llama Suite de Pruebas

-Una Prueba Automatica suele dividiarse en 3 partes o etapas:
 -Preparar (el ambiente para desarrollar la prueba, ejem: generar la data o objetos de prueba, entre otros),
 -Probar (ejecutamos la funcionalidad del software a probar)
 -Verificar (nos aseguramos que obtuvimos el resultado esperado)

Tipos de Pruebas:
	-Pruebas Unitarias
	-Pruebas de Integracion
	-Pruebas de Extremo a Extremo


=======================================================================================
Pruebas Unitarias

-Una prueba unitaria se encarga de probar una unidad de trabajo

-caracteristica:
	-intentan probar una pequeña y aislada parte del software sin importarle las dependencias externas 

-son bastante rapidas

-una prueba unitaria tiende a probar una funcion de una clase (y es normar ver varias prubas unitarias las cuales verifican distinfos funcionamientos de una funcion)


* Por convencion el nombre de una clase de prueba es igual al nombre de la clase a probar terminado en "test o  Pruebas"
* y para el nombre de los metodos dentro de la clase la convencion debe ser [NombreMetodo]_[loQueSeQuiereRetorne]_[bajoQueCondicionDebeOcurrir] (ejemplo : IsValid_RetornaExistoso_SiValueEsVacio)

-por convencion, tengo que probar cada uno de los escenarios que se encuentran en el metodo para así probar que funciona correctamente

-una prueba se divide en 3 etapas: prepacion,prueba y verificacion

-se usa la clase auxiliar "Assert" para realizar las verificaciones

-El atribulo "DataRow" puedo parametrizar algunos valores de mi prueba automatica para asi poder ejecutar la misma prueba pero con distintos valores
